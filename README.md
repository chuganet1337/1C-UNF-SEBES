# Аудит и восстановление себестоимости для 1С:УНФ

Целевая среда: **Управление нашей фирмой 3.0.12.114**, платформа **1С:Предприятие 8.5.1.1302**.

Актуальный файл для проверки в копии базы: `dist/ИСС_АудитСебестоимости_УНФ_3.0.12.114_1.1.3.cfe`.

SHA-256 проверенной сборки: `1D2AEC7E47D45D299AB89327984C7308EADF74FEE0A9AB60C321CDBE8189054D`.

Версия 1.1.3 пересоздана как рабочее место по подходу расширения «Распределение ДС»: интерфейс формируется расширением, чтение и изменение данных разделены, перед опасной операцией строится проверяемый план, результат подробно журналируется.

Все собственные метаданные используют уникальные имена с префиксом `ИСС_`: расширение `ИСС_АудитСебестоимости`, обработка и подсистема `ИСС_АудитСебестоимости`, роль `ИСС_ОсновнаяРольАудитаСебестоимости`, язык `ИСС_Русский`, форма `ИСС_ФормаАудитаСебестоимости`.

Сборку 1.1.0 устанавливать не следует: в ней оставались внутренние UUID коллекций расширения-донора, из-за чего платформа сообщала о конфликте внутренних идентификаторов. В 1.1.1 эти UUID заменены и включены в автоматическую проверку выпуска.

## Что умеет расширение

- детально проверяет регистр `Запасы` на начало периода и после каждого регистратора;
- находит отрицательное количество, отрицательную стоимость, количество без стоимости и стоимость без количества;
- проверяет продажи с нулевой и отрицательной себестоимостью;
- не скрывает повторные проблемы одной номенклатуры;
- позволяет ограничить аудит одной номенклатурой, не сужая опасным образом план восстановления;
- показывает план перепроведения по месяцам и видам документов;
- включает в план все проведенные документы периода и сортирует их по `МоментВремени`;
- до запуска проверяет права чтения и изменения для каждого вида документа;
- требует подтверждения проверенной резервной копии;
- перепроводит неоперативно пакетами по 10 документов;
- останавливается на первой ошибке и сохраняет позицию для продолжения;
- поддерживает остановку пользователем после текущего пакета;
- повторяет аудит после исправления и сравнивает количество проблем;
- ведет читаемый журнал формы и журнал регистрации 1С;
- содержит отдельную проверку структуры регистров УНФ без выгрузки хозяйственных данных.

## Безопасный сценарий работы

1. Установить расширение только в копию базы и проверить применимость.
2. Открыть раздел `Аудит себестоимости`.
3. Нажать `Проверка структуры` и убедиться, что регистры и поля найдены.
4. Выбрать период и выполнить аудит. Фильтр номенклатуры нужен для исследования, но не меняет охват восстановления.
5. Нажать `Сформировать план` и проверить количество документов по месяцам и видам.
6. Создать и проверить резервную копию, вывести пользователей, остановить обмены и фоновые задания.
7. Установить флажок резервной копии и нажать `Перепровести / продолжить`.
8. При ошибке изучить журнал, устранить причину и сформировать новый план. Продолжение с сохраненной позиции допустимо только после проверки, что порядок документов не изменился.
9. Выполнить типовое закрытие каждого затронутого месяца по порядку, от раннего к позднему.
10. Нажать `Контроль после исправления` и сверить типовые отчеты УНФ.

## Важные ограничения

- Расширение не вызывает закрытие месяца автоматически: внутренний интерфейс этой операции должен быть подтвержден непосредственно в целевом релизе УНФ.
- Перепроведение уже выполненных документов не откатывается целиком при поздней ошибке. Каждый успешно проведенный документ остается измененным, а контрольная позиция и ошибка фиксируются в журнале.
- Нулевая себестоимость может быть допустима для отдельных хозяйственных сценариев, поэтому такие строки имеют уровень `ПРОВЕРИТЬ`.
- Статические проверки контейнера не заменяют загрузку в Конфигуратор и приемочный прогон на копии базы.

## Состав репозитория

- `src` — актуальные исходники контейнера расширения;
- `dist` — готовый CFE;
- `tests/Verify-Release.ps1` — структурная проверка выпуска;
- `audit/1.1.3/bsl-json.json` — актуальный отчет BSL Language Server;
- `ИСС_ВосстановлениеСебестоимости_1.0.0` — предыдущий XML-прототип, сохраненный для истории;
- `Аудит_и_проект_расширения.md` — исходный аудит EPF v5.

## Проверка перед эксплуатацией

Обязательные сценарии на копии базы:

- аудит периода без проблем;
- отрицательный остаток, количество без стоимости и суммовой хвост;
- продажа с нулевой и отрицательной себестоимостью;
- повторные нарушения одной номенклатуры;
- фильтр одной номенклатуры;
- план на один и несколько месяцев;
- отсутствие права на один вид документа должно блокировать запуск;
- остановка после пакета и продолжение;
- ошибка проведения в середине плана;
- повторное закрытие месяцев и контроль до/после;
- параллельная работа пользователей должна быть организационно исключена.
