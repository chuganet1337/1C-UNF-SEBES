# Аудит «Диагностика себестоимости УНФ v5» и проект безопасного расширения

Дата анализа: 09.09.2026

Исходный файл: `ДиагностикаСебестоимостиУНФ_анализ_исправление_логи_v5.epf`

SHA-256: `6EC6634804BD19B08E7B86DC0277A361B77A0C1857D0865ADBFB46C8A4B7019D`

Из файла извлечена управляемая форма и модуль формы размером 1361 строка. Вредоносных действий, сетевых вызовов, запуска внешних программ и удаления данных в модуле не обнаружено. Обработка читает регистры УНФ, повторно проводит документы и пишет события в журнал регистрации.

## Как работает имеющаяся обработка

1. Команда «Проверить» анализирует указанный на форме период.
2. Проверяется регистр накопления `Запасы`: состояние на начало периода и изменения по регистраторам внутри периода.
3. Дополнительно проверяется регистр `Продажи` на нулевую и отрицательную себестоимость.
4. В результат выводится не более одной проблемы на номенклатуру.
5. Команда «Перепровести» предлагает выбрать одну номенклатуру.
6. Начальная дата исправления определяется как самое раннее движение этой номенклатуры в одном из девяти жестко заданных регистров.
7. В очередь попадают только документы, в движениях которых уже присутствует выбранная номенклатура.
8. Документы сортируются по `МоментВремени` и повторно проводятся неоперативно пакетами по 10.
9. При первой ошибке выполнение останавливается; уже перепроведенные документы не откатываются.
10. Результат записывается в журнал регистрации. Закрытие месяца автоматически не выполняется.

## Критические замечания

### 1. Очередь не замкнута по связанным товарам

Код выбирает регистраторы только по одной номенклатуре (`Form.obj.bsl`, строки 584–643), но проводит документ целиком (строки 751–781). Если документ содержит другие товары, их движения также пересчитываются. Последующие документы этих товаров в очередь не добавляются. В результате одна позиция может исправиться, а связанные позиции — остаться в нарушенной последовательности.

### 2. Не используется штатное групповое перепроведение УНФ

Обработка напрямую вызывает `ОбъектДокумента.Записать(Проведение, Неоперативный)` (строки 769–771). Она обходит правила штатного рабочего места «Групповое перепроведение документов»: его отборы, исключения, протокол и особенности конкретного релиза УНФ.

### 3. Не выполняется полноценное закрытие месяца

Повторное проведение первичных документов само по себе не гарантирует итоговую себестоимость. После него необходимо повторить регламентные операции закрытия месяца, которые корректируют себестоимость и формируют финансовый результат.

### 4. Частично выполненная операция не откатывается

Каждый документ записывается отдельно. При ошибке цепочка останавливается (строки 783–804), но ранее записанные документы уже изменили данные. В обработке нет устойчивой контрольной точки, продолжения с места ошибки или автоматического восстановления.

### 5. Жесткая зависимость от структуры конкретного релиза УНФ

Аналитика регистра `Запасы` и ресурсы регистра `Продажи` указаны непосредственно в запросах. Проверка существования есть не для всех объектов и полей. При отличии релиза УНФ выполнение завершится ошибкой либо даст неполный результат.

### 6. Диагностика намеренно скрывает часть проблем

После первой найденной строки номенклатура больше не анализируется для вывода результата (строки 953–984). Это удобно для короткого списка, но не является полным протоколом нарушений.

### 7. Некоторые признаки требуют предметной проверки

Нулевая себестоимость продажи и количество без стоимости не всегда означают техническую поломку. Возможны услуги, подарки, начальные остатки, особенности учетной политики и незавершенное закрытие месяца. Автоматически исправлять такие строки только по одному признаку нельзя.

## Решение для расширения

Расширение должно быть оболочкой безопасного восстановления, а не собственной заменой типовых алгоритмов УНФ.

### Этап 1. Предварительная проверка без записи

- показать версию платформы и УНФ;
- проверить наличие штатной обработки группового перепроведения и рабочего места закрытия месяца;
- проверить запрет изменения данных и закрытые периоды;
- сформировать полный список документов и типов документов;
- показать количество документов по месяцам и ожидаемый объем операции;
- не менять данные.

### Этап 2. Резервная копия и блокировка периода

- пользователь подтверждает наличие свежей резервной копии;
- операция выполняется в тестовой копии или в технологическом окне без работающих пользователей и обменов;
- фиксируется начало операции и параметры запуска.

### Этап 3. Штатное групповое перепроведение

- использовать механизм конкретного релиза УНФ;
- перепроводить весь выбранный период, а не отдельную номенклатуру;
- сохранять протокол и останавливаться на первой ошибке;
- поддерживать продолжение после исправления ошибки.

### Этап 4. Закрытие месяца

- повторить закрытие последовательно, от самого раннего измененного месяца к последнему;
- не переходить к следующему месяцу, пока текущий закрыт с ошибкой;
- сохранить протокол регламентных операций.

### Этап 5. Контроль результата

- отрицательные остатки;
- количество без стоимости;
- стоимость без количества;
- отрицательная стоимость;
- продажи с нулевой/отрицательной себестоимостью;
- сравнение контрольных отчетов до и после;
- итоговый журнал документов, ошибок и закрытых месяцев.

## Что необходимо для сборки `.cfe`

Для совместимого расширения нужны:

1. точный релиз УНФ (например, `3.0.xx.x`);
2. версия платформы 1С;
3. выгрузка конфигурации в `.cf` либо XML-выгрузка конфигурации;
4. сведения о доработках и уже подключенных расширениях;
5. тестовая копия базы или обезличенная `.dt` для приемочного прогона.

Без этих данных нельзя корректно заимствовать штатные объекты, определить их идентификаторы и проверить применимость расширения. Сборка универсального `.cfe` «вслепую» для операции, меняющей учетные данные, небезопасна.

## Рекомендуемый временный порядок действий

До готовности расширения не запускать команду «Перепровести» из v5 на рабочей базе. На копии базы использовать штатный путь УНФ: `Настройки → Администрирование → Корректировка данных → Групповое перепроведение документов`, затем выполнить закрытие месяца и контрольные отчеты.
